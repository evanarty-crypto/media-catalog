# Лицензия и атрибуция офлайн-каталога медиа

Файл `assets/data/media_catalog.ru.json` содержит названия, год выпуска и
краткие описания фильмов и сериалов, взятые из **русской Википедии**.

## Источник данных

- Источник: русская Википедия — https://ru.wikipedia.org/
- Способ получения: официальный API MediaWiki (`action=query`,
  `list=categorymembers`, `prop=extracts`).
- Отбор страниц: категории «по алфавиту»:
  - `Категория:Фильмы по алфавиту`
  - `Категория:Телефильмы по алфавиту`
  - `Категория:Мультфильмы по алфавиту`
  - `Категория:Телесериалы по алфавиту`
  - `Категория:Мультсериалы по алфавиту`
- Описания — вступление статьи, обрезанное по границе предложения.

## Лицензия

Текст Википедии распространяется по лицензии
**Creative Commons Attribution-ShareAlike 4.0 International (CC BY-SA 4.0)**:
https://creativecommons.org/licenses/by-sa/4.0/

Атрибуция: «Описания и названия — русская Википедия, CC BY-SA 4.0».

При распространении приложения указание источника обязательно. Если каталог
будет изменён и распространяется дальше, производные данные также должны
оставаться под CC BY-SA 4.0.

## Как обновить каталог

```bash
python3 tool/build_media_catalog.py
```

Скрипт заново скачивает данные из Википедии и перезаписывает
`assets/data/media_catalog.ru.json`, а рядом пишет `media_catalog.version.json`
с версией (ГГГГ.ММ.ДД) и числом записей. Промежуточный прогресс сохраняется в
`assets/data/media_catalog.checkpoint.json` — повторный запуск продолжает
сбор с места остановки. Полный цикл занимает около получаса.

## Два способа доставить обновление

### 1. Вместе с обновлением приложения

Пересоберите приложение — новый каталог попадёт в сборку как ассет:

```bash
python3 tool/build_media_catalog.py
flutter build apk --release
```

Затем выложите новую версию в RuStore. Плюс: ничего не нужно хостить.
Минус: пользователи получают базу только после обновления приложения.

### 2. Отдельно от приложения (без переустановки)

Адрес манифеста уже задан в коде по умолчанию — это файл в публичном
репозитории с базой:

```
https://raw.githubusercontent.com/evanarty-crypto/media-catalog/main/media_catalog.version.json
```

Другой хостинг можно указать при сборке:

```bash
flutter build apk --release \
  --dart-define=MEDIA_CATALOG_MANIFEST_URL=https://ваш-хостинг/media_catalog.version.json
```

Нужна ссылка на сам файл (`raw.githubusercontent.com`), а не страница
просмотра `github.com/.../blob/...` — она отдаёт HTML, и обновление упадёт.

Требования к адресам (проверяются приложением):

- адрес манифеста и адрес архива — только `https`;
- архив из манифеста должен лежать на **том же сервере**, что и манифест.
  Поэтому положить `.gz` на сторонний CDN, а манифест оставить на GitHub,
  не получится: приложение отклонит такое обновление.

Адрес не меняется между релизами — меняется только содержимое файлов на
хостинге. Дальше обновление базы выглядит так:

```bash
python3 tool/build_media_catalog.py        # собрать свежий каталог
python3 tool/publish_media_catalog.py      # подготовить файлы для хостинга
```

Скрипт публикации создаёт в `build/media_catalog_publish/` два файла:

| Файл | Что это |
| --- | --- |
| `media_catalog.ru.json.gz` | сжатый каталог (примерно вчетверо меньше исходного) |
| `media_catalog.version.json` | манифест: версия, число записей, размер, sha256 |

Залейте **оба файла** на хостинг, сохранив имена (GitHub Releases, свой
сервер, объектное хранилище). Пользователи увидят новую версию в
«Настройки → База фильмов и сериалов → Проверить обновление».

Приложение скачивает архив во временный файл, проверяет sha256 и число
записей и только потом заменяет предыдущую базу. Если что-то пошло не так,
остаётся работать прежняя версия; кнопка «Вернуть вшитую базу» сбрасывает
скачанное.

Версии сравниваются как строки, поэтому нумерация ГГГГ.ММ.ДД не даёт
откатиться на более старую базу.
